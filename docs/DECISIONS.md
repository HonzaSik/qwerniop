# Decisions

- Firefox frame-time check: DevTools has no 6× CPU throttle there, so the manual check uses a slow device or OS-level throttling. Reason: keeps the check manual and adds no tooling.
- Ring above (`˚`) compose entry: `Ů` has no dedicated key and the composition table omitted the dead key, so it was unreachable. Reason: all uppercase accented letters are taught as two strokes.
- Other tracks open at letter step 10 for `cs-qwertz`, as LAYOUTS.md already says; the ARCHITECTURE.md sentence now names both layouts. Reason: one per-layout start step keeps `tracksOpen` a lookup.
- Superseded by the owner: step 18 now teaches `ó ď ň ť` as two-stroke dead-key letters. Earlier decision: letter order omitted `ó ď ň ť`: they have no dedicated key and are two-stroke dead-key letters, so lessons do not teach them and words using them are not generated until all letters are unlocked. Reason: LAYOUTS.md lists exactly 17 steps.
- Superseded by the Settings move below (the switcher now lives in Settings): layout switcher sits beside the Length select until the Settings view exists, and the word list loads after storage at startup. Reason: the saved layout decides which list to fetch, and a second control reuses the existing pattern.
- Superseded by the owner (per-layout lesson below): switching layout resets the current lesson to Lesson 1 instead of keeping a per-layout current lesson. Reason: the current lesson is not saved, so one rule fits switch, import and startup.
- The current lesson is remembered per layout: it is saved inside that layout's `progress` record (`lesson: { track, stage }`) when a lesson is started, restored on startup and layout switch, and travels in export and import. `parseProgress` falls back to Lesson 1 when it is not unlocked or no longer exists. Reason: no new store or migration is needed, and the existing write queue keeps it off the keystroke path.
- A missing or unknown `layout` setting reads as `en-us` without a settings version bump. Reason: `migrateSettings` already repairs each field alone.
- Superseded by the Language setting below: UI language follows `navigator.language` (`cs*` is Czech, else English) with no setting yet. Reason: DESIGN.md names no selector, and a setting would change the settings schema and export for no gain before the Settings view.
- `src/core` returns codes instead of English sentences: `feedbackRule`, export `reason`, `noNewKeys`; `lessonTitle` moved to `src/ui/strings`. Reason: core must stay free of display text so each language file holds all of its strings.
- Czech plural forms (1 / 2 to 4 / 5+) use one three-argument `plural` helper, and only where a form differs; other counts are phrased so the noun does not agree. Reason: no i18n package is allowed.
- Design pass: `--space-1` was used but undefined, so the full `--space-1` to `--space-8` set is now in tokens.css; chart tick size and the heading weight use tokens. Reason: DESIGN.md requires every value from tokens.
- Accuracy uses a non-breaking space before `%` in both languages. Reason: Czech typography requires it and one format keeps `formatAccuracy` simple.
- Superseded by the Settings move below (the select now lives in Settings): Reduce motion is a `system` / `on` / `off` select beside Length until the Settings view exists, and App sets `data-reduce-motion` on `<html>`; all motion CSS is scoped to `:root:not([data-reduce-motion])` instead of media queries. Reason: one mechanism lets the setting override the OS in both directions with no per-component logic.
- `reduceMotion` is missing or unknown reads as `system` without a settings version bump. Reason: `migrateSettings` already repairs each field alone.
- Help sheet is a native `<dialog>` in App, opened with `?` through `showModal()` and closed by Esc or its Close button. It opens only when the key target is not an input, select or textarea and the key was not already used, so `?` still types in a passage and a key that resumes a paused session does not open it. Reason: the browser supplies focus trapping, Esc and the dialog role.
- `Esc` pauses a session by blurring the textarea, which reuses the existing blur pause; on Lessons and Stats it returns to Practice. Reason: no second pause path.
- The `,` (settings) shortcut is not implemented until the Settings view exists, and the help sheet lists only working shortcuts. Reason: a shortcut to nowhere would be a placeholder.
- One global `:focus-visible` rule in App.svelte draws the ring; per-component ring rules are deleted. Reason: one rule covers every present and future control.
- Screen reader support: `<html lang>` is set from the UI language at startup, the timer has `role="timer"` (implicitly not live, so seconds are not announced), and the textarea is described by the passage element (read once on focus). Lessons and Stats keep landmark plus `h2` sections without an `h1`. Reason: a per-keystroke position description would add DOM work on the keystroke path, and the landmark names already identify each view.
- The touch-device message is a status line above the passage, styled like the pause message, and is shown once at mount from `(pointer: coarse) and (hover: none)`; its keydown listener is removed at the first physical `event.code` and the message never returns in that page load. Reason: the media query is not re-evaluated, so no per-keystroke check remains.
- Service worker shell list is stamped into `dist/sw.js` by `scripts/stamp-sw.mjs` after the build, and all same-origin GETs are cache-first. Reason: a hand-written list cannot know hashed names, and the stamp is also what makes each build's `sw.js` differ so updates are detected.
- Manifest uses one `icon.svg` and light theme colours (`#ffffff`); the page has light and dark `theme-color` meta tags. Reason: web manifests have no dark variant, and an SVG avoids binary assets.
- The practice font ships one file, JetBrains Mono Regular (400) only, with no 600: practice text is never bold and PERFORMANCE.md asks for one font file. Reason: fewer bytes and no faux-bold risk; the dialog and other 600 text use the interface font.
- The font subset is recorded as an exact `pyftsubset` command in `src/data/SOURCES.md`, not a script in `scripts/`. Reason: it runs once per font release and needs a Python tool outside the project's dependencies.
- The font is listed in the service worker shell by the stamp (every `dist` file except `.txt`), so it is cached at install, not only on first load. Reason: it is needed on the first paint offline and the existing stamp already covers it with no code.
- Provider failures throw `ProviderError` with a `kind` (`network`, `http`, `timeout`, `bad-response`, `server`); a fetch `TypeError` is `network`, which Settings later maps to the CORS hint. A caller abort rethrows the native abort error. Reason: callers need to tell a CORS-looking failure and a timeout from a deliberate cancel without parsing messages.
- `createOpenAiProvider` takes the model in its options, so `stream` keeps the AI.md signature; `listModels` uses the 5 s limit. SSE parsing lives in a pure `src/ai/sse.ts` that skips malformed lines. Reason: AI.md's interface has no model parameter, and a skipped line should not end a generation.
- Superseded by the Settings move below: the Settings view (`#settings`, nav link and `,` shortcut) holds only the model server section for now; the interim Layout, Length and Reduce motion selects stay on Practice. Reason: DESIGN.md says those move when the Settings view exists but this item is one section, and moving them is a separate change.
- `modelServer` (`baseUrl`, `model`, `apiKey`) is a settings field validated per field; the "Enabled" switch and mode toggles wait for the first mode that reads them. Reason: fields are added with the feature that reads them.
- Export drops `modelServer` and import keeps the device's own. Reason: ARCHITECTURE.md excludes model server settings, and an import must not wipe the key.
- Test connection loads `src/ai` with a dynamic `import()` on click; only a `network` failure shows the CORS help. The model is a select filled from the last test, and a test with no valid saved model picks the first one. Reason: AI.md says the model is chosen from the server's list, and CORS is the only failure the hint explains.
- `validate(raw, options)` in `src/ai/validate.ts` returns the cleaned text or `undefined` (use offline content); options are `lesson` (allowed characters), `topic`, `feedback` and `code` (a layout), each with `min` and `max` in characters. Reason: one pure function with one failure value fits every mode and lets core's `strokesFor` decide what is typable.
- Validation drops a first line that ends in `:` when more lines follow (a preamble such as "Here are some sentences:"), and code mode takes only the first fenced block. Reason: real model output wraps answers in introductions and explanations that the six rules do not cover.
- Lesson text is strict: punctuation counts as a character, so words with punctuation survive only if the caller lists it in the allowed set. Reason: AI.md rule 4 removes any word with a character outside the set.
- Code mode keeps newlines, asterisks and inner spacing, expands tabs to four spaces, trims trailing spaces, and discards the whole snippet if any character cannot be typed. Reason: dropping or transliterating a character changes what the code means.
- The length clamp cuts at the last word (or line, for code) boundary within `max` and discards a result shorter than `min`. Reason: AI.md only says "clamp to the requested range".
- Fixtures in `tests/fixtures/ai/` are single JSON files (`model`, `system`, `prompt`, `output`) captured verbatim from local `gemma4:12b` and `qwen2.5-coder:14b`; `-lax` fixtures use a plain assistant prompt to capture Markdown and chatter. Reason: the strict prompts alone produce nearly clean output.
- `modelServer` also holds `enabled` (default off), `modes` (four switches, default on) and `topic`; the switches show in Settings only while enabled. Reason: AI.md lists them as settings, and they stay out of export with the rest of `modelServer`.
- Mode selection is `planMode` in `src/ui/ai.ts`: letters track uses Learn a topic once every letter is unlocked and a topic is set, otherwise Lesson text from 12 letters; code uses model snippets from code stage 4 (whole snippets); punctuation and numbers stay offline. Reason: AI.md ties each mode to a stage, and code stages 1 to 3 restrict symbols that validation does not check.
- Superseded by the prefetch entry below (generation no longer happens on demand with an 8 s bound): generation is on demand when a lesson starts: one request bounded by 8 s, then offline text with no message; summary feedback is requested after the offline sentence shows and replaces it when it arrives. Reason: prefetching is the next roadmap item, and a bounded wait keeps typing never blocked.
- Superseded by the owner (length-following entry below): lesson text asks for at most 40 words and the passage ends the session even if the length setting is longer; topic passages ask for 150 to 600 characters. Reason: small models drift on long outputs, and a short model text beats a failed one.
- Learn a topic keeps only the tail (200 characters) of the last passage in memory as its continuity summary; stored history and the recap question were added afterwards (see below). Reason: AI.md's summary is approximated by the tail.
- Superseded by the owner (fingers-and-trend entry below): session feedback prompt sends WPM, accuracy and the weakest key labels, without finger names or trend. Reason: the offline summary has neither (DESIGN.md), and statistics stay minimal.
- Prompts for code are English in both languages and ask for JavaScript only, matching the offline snippet data. Reason: identifiers and keywords are English, and there is no language setting.
- `src/ai/modes.ts` turns every stream error, abort or rejected validation into `undefined`. Reason: AI.md says failures are silent and fall back to offline content.
- Topic history is kept in a new `topics` IndexedDB store (migration 2), keyed by the topic text, as `{ count, passages }`: the newest 6 passages plus the total count. Reason: continuity needs the latest passage and a recap needs a few; the cap keeps each topic to a few kilobytes. Topics themselves are not capped, since each is one typed string.
- Topic history is not exported or imported, and import leaves the `topics` store alone. Reason: ARCHITECTURE.md lists only settings, progress and sessions, and a generated-text cache is device data like the model server settings.
- Continuity now uses the last 200 characters of the newest stored passage, so reopening the app continues the topic; this replaces the in-memory tail. The history loads once per topic when the first passage is requested and is saved through the write queue after each passage.
- The recap question is requested every 3rd passage (`RECAP_EVERY`) after the session ends, like the feedback sentence, so it never delays a lesson; it uses the last 3 passages, passes the topic validation rules (15 to 250 characters), shows under the feedback sentence as plain text with the label "Think about it:", and is silently skipped on any failure. Reason: AI.md says "every few passages" and "optional".
- Prefetching: `src/ui/prefetch.ts` (pure, no Svelte) keeps one result for one key; an effect in App requests the next passage (the lesson after the current one, under current progress) and a changed key aborts the stale request. A session start takes the result only if it is ready, otherwise uses offline text at once; the 8 s bound is gone and the provider's own 30 s limit ends a stuck request. Reason: AI.md rule 2 forbids a visible wait.
- The key is the mode, server address, model, layout, lesson, letter stage, topic (topic mode) and length (lesson mode); weak letters are not in it. Reason: stats change after every session, and a slightly older weak list is not worth discarding a ready passage.
- The recap now travels with the generated passage and is asked for after that passage is typed; a topic passage that was prefetched but never shown still stays in the stored history. Reason: a prefetched passage finishes during the previous one and must not trigger its recap early, and tracking unshown passages would need a second history.
- The first run after loading is always offline; the prefetch result is used from the next session start. Reason: using it would put a wait or a text swap on a visible passage.
- The ai chunk is checked in `scripts/size-check.mjs`: `vite.config.ts` names any chunk holding `src/ai` code `ai-*.js` (`chunkFileNames`), and the check fails if one is reachable from `index.html` scripts or modulepreloads through static imports. Reason: `manualChunks` pulled the shared preload helper into the ai chunk and made the entry import it, so naming chunks is the reliable option.
- `generatedRecap` also returns early for a disabled server or empty model. Reason: it was the one entry into `src/ai` without the check, so disabling the server mid-session could still load the chunk.
- README screenshots: one Practice view per scheme (`docs/screenshots/practice-{light,dark}.png`, 1280x800), linked with a `<picture>` element. Reason: it is the main screen and shows keyboard and text; more images would go stale faster.
- Issue templates are two GitHub issue forms (bug report, feature request) with no `config.yml`; the pull request template mirrors the checks in CONTRIBUTING.md. Reason: forms make the bug fields (browser, OS, layout, model server) required, and blank issues stay allowed for a small project.
- Pages: `.github/workflows/pages.yml` runs on push to main and manual dispatch, repeats check, test and build (same setup as `ci.yml`), then uploads `dist/` and deploys with the official Pages actions. Reason: a separate workflow cannot wait on CI without extra triggers, and the repeat is a minute of work.
- `vite.config.ts` sets `base: "./"`. Reason: a project site lives at `/<repo>/`, and relative URLs make one build work there and at a domain root with no env var; the font in CSS, word lists (`new URL(..., import.meta.url)`), the manifest, the worker registration and the stamped shell list were already relative or are rewritten by Vite, and `size-check` still finds the assets.
- Release notes live in `CHANGELOG.md` (Keep a Changelog) under `## [Unreleased]`, with no date. Reason: 1.0.0 is not tagged yet, and the heading becomes `[1.0.0] - <date>` in the release step.
- `package.json` stays at `0.0.0`; the roadmap item covers notes only. Reason: bumping and tagging are human release steps, now listed in MANUAL_CHECKS.md.
- `docs/MANUAL_CHECKS.md` was overwritten with a copy of AI.md in commit 93d2f13; it is restored from b04823a plus the later sections (prefetching, ai chunk, screenshots, Pages). Reason: the release step needed the file, and the manual checks were lost.
- License holder stays "Tenfold contributors" in LICENSE, with no author field in package.json. Reason: no full name is recorded anywhere in the repository and one is not invented.
- Layout, Length and Reduce motion moved from the top right of Practice into Settings groups General, Practice and Accessibility; the Keyboard select stays under the keyboard. Reason: DESIGN.md put them there once the view existed, and the keyboard control is tied to what it changes on screen.
- `language` setting (`system` / `en` / `cs`, default `system`, no version bump) is exported and imported with the other settings; `t` is a `Proxy` over the current strings so existing `t.x` reads in templates become reactive without changes. Reason: it is a personal preference like layout, not a device secret; a Proxy avoids threading strings through every component.
- Lesson-mode model text follows the length setting: the session needs `words` words (15/30/60, or `seconds * 4` when timed), the request asks for `min(words, 80)` words (`LESSON_REQUEST_WORDS`), model text beyond `words` is cut, and a shortfall is topped up with offline `generate` words using the same letters, stats and targets. Reason: small models drift on long outputs, so a timed session of up to 480 words is mostly offline, and the session length is always honoured.
- Session feedback prompt sends WPM, accuracy, the weakest key labels, the fingers of those keys (via `fingerFor`) and the average WPM and accuracy of the previous 5 sessions of the layout (`TREND_SESSIONS`, absent on a first session); never typed text. Reason: AI.md mode 4 lists fingers and trend as input; the finished session is read back from storage and excluded from its own trend.
